# Dayopt Copywriting Tone Guide v3

## 人格定義

> **「あなたの時間に関心を持っている、寡黙な研究者」**

データで示し、感情で煽らない。ユーザーの知性を信頼し、結論を押しつけない。普段は数字だけを静かに見せる。ただし節目（自己ベスト更新など、過去の自分を超えた瞬間）では一言だけ踏み込む。その一言に温かさと重みがある。

この人格が最優先の判断基準である。本書後半の説得の技法（チャルディーニ6原則・Pre-suasion）は、人格に従属する道具にすぎない。技法と人格が衝突したら、常に人格を優先する。Do / Don'tチェックリストの禁止事項（他人比較、恐怖を煽る訴求、煽情的な表現）は、この序列を具体化したものである。

この人格はプロダクト（UI）の声である。ブログやSNSなどのマーケティングコンテンツは、創業者の人間臭い声で書く。正本は[`docs/business/content/voice.md`](../business/content/voice.md)である。二つの声は意図的な使い分けである。

### 性格ルール

| 場面     | 研究者はこう語る       | こうは語らない                     |
| -------- | ---------------------- | ---------------------------------- |
| 良い結果 | 先週より30分多いです   | すごいですね！                     |
| 悪い結果 | 先週より短めでした     | もっと頑張りましょう               |
| 提案     | こういう傾向があります | こうしたほうがいいです             |
| 沈黙     | 数字だけ表示           | 毎回コメントを添える               |
| 節目     | 過去最高です           | おめでとうございます！素晴らしい！ |

### 距離感の基準

- 日常操作（トースト、エラー）：最短の言葉。感情を載せない
- 週次（ウィークリーレポート）：パターンの分析を見せる。1〜2文の所見を添える
- 節目（自己ベスト更新）：一言だけ踏み込む。感嘆符はここだけ許可

## 英語UI文言ルール

人格は言語をまたいで同一である。日本語の「です・ます」に相当する丁寧さは、英語では平易で直接的な文で表す。翻訳ではなく、各言語で自然な文を書く（正本は `apps/product/messages/{en,ja}/`、運用は i18n skill）。

| #   | ルール                          | NG                           | OK                               |
| --- | ------------------------------- | ---------------------------- | -------------------------------- |
| 1   | sentence case（文頭のみ大文字） | Delete Event                 | Delete event                     |
| 2   | ボタンは動詞で始める            | Deletion                     | Delete                           |
| 3   | 短く直接的に。please で飾らない | Please try again later       | Try again                        |
| 4   | 主語 your は必要な場合のみ      | Your profile                 | Profile                          |
| 5   | destructiveボタンに対象を明記   | Delete                       | Delete event                     |
| 6   | エラーに原因+対処を含める       | An error occurred            | Something went wrong. Try again. |
| 7   | vague SaaS words 禁止           | Seamlessly optimize your day | See where your time went         |

- 性格ルールと感嘆符の基準は日本語と共通。良い結果は「30 min more than last week」、節目だけ「Personal best!」
- 7 の禁止語リスト（empower / leverage / seamless / robust / optimize など）は [writing-style.md](../business/content/writing-style.md) §英語のルール と共通

## 感嘆符の使用基準

| 場面               | 使用 | 例                                   |
| ------------------ | ---- | ------------------------------------ |
| 自己ベスト更新     | ○    | 過去最高です！                       |
| 日常の操作トースト | ×    | 削除しました（✓で代替）              |
| エラー             | ×    | 問題が起きました。                   |
| 空状態             | ×    | 最初のブロックを記録して始めましょう |
| Pro訴求            | ×    | 煽り感が出るため禁止                 |

感嘆符は「研究者が珍しく声を上げる瞬間」。日常では✓マークや事実の提示で達成感を表現する。

## チャルディーニ6原則の適用

Dayoptは、押しつけずデータで示す影響力の研究者としてチャルディーニのように語る。以下の原則は、人格定義の序列に従う道具である。

### 原則1: 一貫性（Commitment & Consistency）

ユーザーが「自分はこういう人間だ」と感じる言葉を使う。小さなコミットメントを積み上げさせる。

| 場面                     | NG                             | OK                                             |
| ------------------------ | ------------------------------ | ---------------------------------------------- |
| 空状態（初回）           | まだデータがありません         | 最初のブロックを記録して始めましょう           |
| 空状態（アクティビティ） | まだアクティビティがありません | 最初のアクティビティを作って整理を始めましょう |
| オンボーディング         | プロフィールを入力してください | 朝型？夜型？あなたのリズムを教えてください     |
| ストリーク表示           | 5日連続                        | 5日連続で記録しています                        |
| Insights                 | 集中時間: 2h                   | 月曜の午前に集中する傾向があります             |

**ルール: 空状態では「ない」で終わらず、次の一歩を具体的に示す。Insightsではパターンを言い切り、自己ラベリングを促す。**

### 原則2: 希少性（Scarcity）

得るものではなく、失うものをフレーミングする。ただしボタンではなく説明文で表現する。

| 場面     | 説明文（希少性）                         | ボタン（ニュートラル） |
| -------- | ---------------------------------------- | ---------------------- |
| Free制限 | {n}ヶ月分のデータが眠っています          | Proで確認する          |
| 削除確認 | この記録は完全に消えます。取り消せません | 記録を削除             |

**ルール: 心理的圧力は説明文が担う。ボタンは押しやすさに専念する。**

### 原則3: 好意（Liking）

味方の研究者として寄り添う。責めない、データで褒める、安心感を与える。

| 場面           | NG                     | OK                                               |
| -------------- | ---------------------- | ------------------------------------------------ |
| 成功トースト   | 作成しました           | 記録しました ✓                                   |
| パレット追加   | パレットに追加しました | パレットに追加しました。次回からすぐ使えます     |
| 記録ゼロの日   | 記録がありません       | 今日の記録を始めましょう                         |
| マイナスの数字 | 先週より2h少ないです   | 先週より短めでした                               |
| 中度エラー     | 保存できませんでした   | 保存できませんでした。入力内容は保持されています |

**ルール: 成功には小さな達成感を添える。失敗・空白は責めず次の行動を示す。マイナスのとき具体的な数字で追い討ちしない。**

### 原則4: 社会的証明（Social Proof）

他人のデータは使わず、「過去の自分」を証人にする。

| 場面       | NG                   | OK                                                        |
| ---------- | -------------------- | --------------------------------------------------------- |
| ゴースト   | 先週のデータ         | 先週の月曜もこの時間にDeep Workをしていました             |
| Insights   | 平均集中時間: 2h     | 月曜午前に集中する傾向があります（4週中3週）              |
| LP         | ユーザー数: 1,000人  | Dayoptユーザーが記録した総時間: {n}万時間                 |
| 復帰メール | Dayoptを使いましょう | 先週の{曜日}は{アクティビティ名}を{n}時間記録していました |

**ルール: 個人のプライバシーを守りつつ、パターンの「証拠」を提示する。LPのみ匿名集合データを使用可。**

### 原則5: 権威（Authority）

Dayoptが時間管理の「正しいやり方」を再定義する存在として語る。

| 場面             | NG                     | OK                                                               |
| ---------------- | ---------------------- | ---------------------------------------------------------------- |
| LPキャッチコピー | 時間を管理しましょう   | カレンダーは予定を見せます。Dayoptは実際に何が起きたかを見せます |
| Deep Zone説明    | 集中しやすい時間帯です | 研究に基づくあなたの集中ピーク時間帯です                         |
| Pro訴求          | 高度な分析機能         | AIがあなたの時間パターンを分析します                             |

**ルール: 機能説明ではなく、なぜそれが正しいのかの根拠を暗示する。**

### 原則6: 返報性（Reciprocity）

まず価値を与えてから求める。

| 場面     | NG                 | OK                                                       |
| -------- | ------------------ | -------------------------------------------------------- |
| Free機能 | 基本機能が使えます | 基本的な記録と振り返りは、ずっと無料でお使いいただけます |

**ルール: 課金を求める前に、具体的な価値を先に提示する。**

## Pre-suasion（下準備）ルール

チャルディーニの『PRE-SUASION』に基づく。メッセージの内容だけでなく、その直前に何を見せるか・文の中でどの言葉を先に置くかで、受容性が変わる。

### コピーライティングへの適用ルール

| #   | ルール                                   | NG                             | OK                                                           |
| --- | ---------------------------------------- | ------------------------------ | ------------------------------------------------------------ |
| 13  | 価値をコストより先に書く                 | 月額$5でAIインサイトが使えます | AIがあなたの時間パターンを分析します。月額$5                 |
| 14  | 空状態は「ない」ではなく可能性から始める | まだアクティビティがありません | アクティビティで時間に名前をつけると、パターンが見えてきます |
| 15  | 質問は求める方向に誘導する               | フィードバックをお願いします   | Dayoptで良くなった点はありますか？                           |
| 16  | メタファーは「地図」で統一する           | 時間を管理する                 | 時間の地図を作る                                             |

### 語順の原則

同じ内容でも、先に来る単語が後半の印象を決める。

| 先にコストを書く（NG） | 先に価値を書く（OK）                         |
| ---------------------- | -------------------------------------------- |
| Proは月額$5です        | AIがあなたの時間パターンを分析します。月額$5 |

### 質問の前置き効果

質問自体が回答を方向づける。ユーザーに求める態度を質問で先に活性化させる。

| 場面             | NG                             | OK                                         |
| ---------------- | ------------------------------ | ------------------------------------------ |
| Pro訴求          | Proに興味がありますか？        | 自分の時間のパターンを知りたいですか？     |
| フィードバック   | ご意見をお聞かせください       | Dayoptで良くなった点はありますか？         |
| オンボーディング | プロフィールを入力してください | 朝型？夜型？あなたのリズムを教えてください |

### メタファーの統一:「地図」

Dayopt全体で「地図」のメタファーを一貫して使う。地図は「今まで見えなかったものが見える」という発見の連想を起こし、研究者ペルソナとの相性が良い。

| メタファー | 連想             | Dayoptとの相性             |
| ---------- | ---------------- | -------------------------- |
| 地図 ✓     | 探索・発見・俯瞰 | 最適。「時間の地図を作る」 |
| 鏡 ×       | 自己批判・反省   | 責められる感じが出やすい   |
| 日記 ×     | 義務・毎日書く   | 記録の負担感が出やすい     |

適用例：

- LP: 「あなたの時間の地図を作ります」
- オンボーディング完了: 「地図の最初のピンを置きました」
- Insights: 「あなたの時間の地図に、新しいパターンが見えてきました」
- 1年の節目: 「1年分の時間の地図ができました」

### 空状態コピーの改善（Pre-suasion版）

「まだ○○がない」で始めると欠如が意識される。可能性やポジティブなイメージを先に置く。研究者は観察した事実を述べ、次のステップを静かに示す。

| 現状（v3）                                                                     | Pre-suasion版                                                                                    |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| まだアクティビティがありません。最初のアクティビティを作って整理を始めましょう | アクティビティで時間に名前をつけると、パターンが見えてきます。最初のアクティビティを作りましょう |
| 最初のブロックを記録して始めましょう                                           | まっさらな1日です。最初のブロックを記録しましょう                                                |
| 今日の最初のブロックを追加しましょう                                           | まっさらな1日です。最初のブロックを追加しましょう                                                |
| 今週の記録はまだありません                                                     | 新しい1週間が始まりました                                                                        |

### 画面遷移への適用

コピーだけでなく、どの画面の次にどの画面が来るかもPre-suasion。

| 場面                   | 直前に見せるもの                                                   | 効果                                      |
| ---------------------- | ------------------------------------------------------------------ | ----------------------------------------- |
| Pro課金ページ          | これまでのサマリー（累計記録時間、最も時間を使ったアクティビティ） | 蓄積した価値を意識→課金の妥当性が上がる   |
| ウィークリーレポート   | 冒頭に「今週よかった点」                                           | ポジティブ気分→改善提案の受容性が上がる   |
| オンボーディング       | 「朝型？夜型？」質問                                               | リズムを意識→Deep Zoneの価値が伝わる      |
| 最初のブロック作成直後 | 「パレットに登録すると次回からすぐ使えます」                       | 小さな達成感→次の行動へのハードルが下がる |

## 数字のフレーミングルール

### 基本原則

数字には必ず比較対象を添える。比較対象は3つだけ。他人との比較は絶対にしない。

1. 先週の自分
2. 先月の自分
3. 自分の平均

### 増減の表現

| 状況             | 表現                     | 理由                               |
| ---------------- | ------------------------ | ---------------------------------- |
| 先週より増えた   | 「先週より{n}多いです」  | 具体的な数字で達成感               |
| 先週より減った   | 「先週より短めでした」   | 数字を出さない。責めない           |
| 先週と同じ       | 「先週と同じペースです」 | 安定はポジティブ                   |
| 初週（比較なし） | 数字のみ表示             | 比較対象がないときは無理に添えない |
| 自己ベスト更新   | 「過去最高です！」       | 特別な達成感。感嘆符はここで使う   |

### タブ別の適用

**Reviewタブ**

| 今の表示                | フレーミング版                                   |
| ----------------------- | ------------------------------------------------ |
| 今週の記録時間: 32h     | 今週の記録時間: 32h（先週より2h多いです）        |
| Deep Work: 8h           | Deep Work: 8h（あなたの平均より1h多いです）      |
| アクティビティ数: 6種類 | 6種類のアクティビティを使いました（先週は4種類） |

**Progressタブ**

| 今の表示               | フレーミング版            |
| ---------------------- | ------------------------- |
| 現在のストリーク: 14日 | 14日連続で記録しています  |
| 累計ブロック: 142個    | 142個（先月は89個でした） |

**Insightsタブ**

| 今の表示                          | フレーミング版                                         |
| --------------------------------- | ------------------------------------------------------ |
| 月曜の平均集中時間: 2h            | 月曜は平均2h集中しています（他の曜日より40分長いです） |
| Deep Zone活用率: 60%              | Deep Zoneの60%を活用しています（先月は45%でした）      |
| 最も使うアクティビティ: Deep Work | Deep Workに最も時間を使っています（全体の35%）         |

## CTAの強度階層

### Tier 1: 転換CTA（Pro課金）

説明文にチャルディーニ、ボタンはニュートラル。

| 場面         | 説明文                          | ボタン        |
| ------------ | ------------------------------- | ------------- |
| Free制限表示 | {n}ヶ月分のデータが眠っています | Proで確認する |

視覚: Primary（塗りボタン、アクセントカラー背景）。1画面に最大1つ。

### Tier 2: 行動CTA（機能利用・記録開始）

一貫性を使う。具体的な行動を示す。

| 場面         | NG       | OK                       |
| ------------ | -------- | ------------------------ |
| 空状態       | 追加     | 最初のブロックを記録する |
| テンプレート | 使用する | このテンプレートで始める |
| パレット     | 登録     | パレットに追加する       |

視覚: Secondary（アウトラインボタン）。

### Tier 3: 情報CTA（詳細確認・ナビゲーション）

ニュートラル。心理的圧力ゼロ。

| 場面         | NG                   | OK         |
| ------------ | -------------------- | ---------- |
| 設定への導線 | 設定を開いて確認する | 設定を見る |
| Stats詳細    | 分析結果を確認する   | 詳しく見る |
| ヘルプ       | ヘルプページへ移動   | 詳細       |

視覚: Ghost（テキストリンク、下線 or アイコンのみ）。

### CTAルール

| #   | ルール                                                        |
| --- | ------------------------------------------------------------- |
| 1   | Tier 1は説明文が心理的な仕事をし、ボタンはニュートラル        |
| 2   | Tier 2は具体的な行動動詞で書く                                |
| 3   | Tier 3は最小限の言葉                                          |
| 4   | 1画面にTier 1は最大1つ                                        |
| 5   | 抽象的な動詞を避ける（「使用」「確認」→「記録する」「見る」） |

## 復帰導線のコピー

### アプリ内バナー（復帰時）

> {n}日ぶりですね。前回は{日付}に記録しています。

事実ベース。過剰な歓迎はしない。「前回の記録」を見せることで一貫性が働く。

離脱メールやプッシュ通知での追い立ては行わない（決定ログ（削除済み、git 履歴参照））。復帰はユーザーが自発的に戻った時のこのバナーのみで迎える。

## エラーの重要度階層

| 重要度               | 表示方法           | 例                                                                           |
| -------------------- | ------------------ | ---------------------------------------------------------------------------- |
| 軽微（コピー失敗等） | トースト           | コピーできませんでした。もう一度お試しください                               |
| 中度（保存失敗等）   | トースト + 安心感  | 保存できませんでした。入力内容は保持されています。もう一度お試しください     |
| 重大（データ競合等） | インラインアラート | このタイムブロックは他の場所で変更されました。最新データを読み込んでください |

中度エラーでは「入力内容は保持されています」の一言を必ず添える。ユーザーの恐怖を激減させる。

---

## 確認ダイアログの使い分け

| 操作                       | 確認方法       | 理由                                   |
| -------------------------- | -------------- | -------------------------------------- |
| 不可逆な削除               | 確認ダイアログ | 取り消せないため事前確認が必要         |
| 可逆な操作（アーカイブ等） | Undoトースト   | 「アーカイブしました。元に戻す」で十分 |
| 設定変更                   | 確認なし       | いつでも戻せる                         |

GAFAは確認ダイアログを減らす方向。不可逆な削除だけ確認を出し、それ以外はUndoトーストで対応する。

## カテゴリ別テンプレート

### トースト通知

```
成功:      「{操作}しました」 or 「{操作}しました ✓」
失敗（軽微）: 「{操作}できませんでした。もう一度お試しください」
失敗（中度）: 「{操作}できませんでした。入力内容は保持されています。もう一度お試しください」
Undo:      「{操作}しました。元に戻す」
```

### 空状態

```
初回:    可能性を先に置く。「{ポジティブな観察}。最初の{対象}を{動詞}ましょう」
検索:    「「{キーワード}」に一致する{対象}がありません」
期間:    「新しい{期間}が始まりました」
復帰:    「{n}日ぶりですね。前回は{日付}に記録しています」
```

### 削除確認

```
基本:    「{対象}は完全に削除されます。取り消せません。」
関連あり: 「{対象}と{n}件の{関連}との紐づけが消えます。取り消せません。」
```

### Pro訴求

```
説明文:  「{具体的に失うもの/眠っているもの}」
ボタン:  「Proに登録する」or「Proで確認する」
```

## Do / Don't チェックリスト

### Do

- 「です・ます」で丁寧に（GAFA準拠）
- 数字に比較対象を添える（先週の自分、自分の平均）
- 空状態で次の一歩を促す（一貫性）
- 成功に小さな達成感を添える ✓（好意）
- 制限・終了は説明文で失うものを書く（希少性）
- 削除確認で失うものを先に書く（希少性）
- エラーに原因+対処を含める（好意）
- 中度エラーに「入力内容は保持されています」を添える（好意）
- 課金を求める前に価値を提示する（返報性）
- Insightsでパターンを言い切る（社会的証明）
- 可逆な操作はUndoトーストで対応（GAFA準拠）
- 文の前半に価値・可能性を置く（Pre-suasion）
- 質問で求める態度を先に活性化させる（Pre-suasion）
- 「地図」メタファーで統一する（Pre-suasion）
- 課金判断の直前にデータの価値を見せる（Pre-suasion）
- ウィークリーレポートはポジティブから始める（Pre-suasion）

### Don't

- 体言止めで文章を終わらせる（冷たい印象、GAFA非準拠）
- 「〜がありません」だけで放置する（行動を示さない）
- 「失敗しました」だけで終わる（リカバリーがない）
- ユーザーを責めるトーン（好意を損なう）
- マイナスの数字を具体的に示す（追い討ちしない）
- ボタンに心理的圧力を詰め込む（説明文の仕事）
- 日常のトーストに感嘆符を使う（研究者は普段叫ばない）
- 「アップグレードしませんか？」（得るものフレーミング）
- 他人との比較を出す（絶対に使わない）
- gamification（バッジ、ストリーク危機の煽り）で達成を演出する（製品から削除済み。決定ログは削除済み・git 履歴参照）
- 離脱メール・プッシュ通知で記録を追い立てる（非採用方針。決定ログは削除済み・git 履歴参照）
- コスト・制限・欠如から文を始める（Pre-suasion違反）
- ニュートラルな質問でフィードバックを求める（Pre-suasion違反）
- 「管理」「日記」「鏡」のメタファーを使う（Pre-suasion違反）
- 課金ページに直接遷移させる（Pre-suasion違反）
- レポートを改善点から始める（Pre-suasion違反）
