# Review（振り返り）

`/report` は週 / 月 / 年で切り替わる **目的別 3 タブの読み物**（時間の使い方 / 差分 / 振り返り）。Plan と Record の距離を静かに示し、次の計画へ渡すための面。ダッシュボードではない。

## 0. 原則

台帳は評価しない。この 6 つに反する実装は、要望があっても入れない。

1. **タブは目的で固定する**。タブの追加・並び替え・非表示・ウィジェットのカスタマイズを持たない。期間（週 / 月 / 年）はタブと独立した軸
2. **評価しない**。スコア・ストリーク・カバー率・目標・達成率・推奨文・色による良し悪しを作らない
3. **数字は必ず明細に落ちる**。クリックできる数字・バー・点はすべて詳細パネル（またはカレンダー）へ着地する
4. **統計の誠実さ**。平均を出さない（中央値と `n` で語る）。閾値未満は数字を作らず沈黙する
5. **配分の分母は記録時間の合計**。書かれていない時間は「余白」と呼んで見出しに数字で出すだけで、**配分に混ぜず、灰色ブロックでも塗らない**
6. **レポート面では作成・編集をしない**。詳細パネルの明細からカレンダーへ飛ぶことだけがアクション

文言は責めない・催促しない（「〜しましょう」「〜すべき」を使わない）。

## 1. 3 タブ

| tab（`?tab=`）  | ラベル       | 読むもの                  | 中身（面）                                                                                                                                                                 |
| --------------- | ------------ | ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `usage`（既定） | 時間の使い方 | 事実 — 何にいくら使ったか | 数字のカード 3 枚（記録時間 / 記録件数 / 1 件の中央値、それぞれ前期間比）/ 日ごとの記録時間 / 配分の横棒 / アクティビティ一覧 / 時間帯の分布（0〜23 時）/ 1 件の長さの分布 |
| `diff`          | 差分         | 予定と記録はどう違ったか  | 執行: アクティビティ別の 記録バー + 予定バー（破線）+ 予定比 / 見積もりの鏡                                                                                                |
| `reflect`       | 振り返り     | それは良い使い方だったか  | 質: 羅針盤（投下時間 × 充実）と、点になるのを待っているアクティビティ                                                                                                      |

- 期間の集計（`review.getReportPeriod`）はタブに依存しない。タブの切替は描く面を変えるだけで、サーバーへ往復しない
- 旧 4 章「整える」（未分類の記録 / 未変換の外部予定 / 次期間の予定時間）は 2026-09-15 に撤去した
- **時間の使い方の配分は記録時間の合計を 100% にする**（2026-09-15 User 裁可）。余白は見出しの数字にだけ出し、配分には混ぜない。図は横棒（名前・棒・時間・割合を同じ行に）。円グラフは作らない
- 配分の内訳の単位は見えている集合から導く（`resolveAllocationMode`）: 記録のあるカテゴリーが 2 つ以上 → カテゴリー別 / カテゴリーが 1 つでアクティビティが 2 つ以上 → その配下のアクティビティ別 / アクティビティが 1 つだけ → 配分を省く（自分自身の 100% は出さない）
- アクティビティ一覧は記録のある行を全部出す（足切りしない）。既定は記録時間の多い順、前期間との差の順へ切り替えられる。行を押すと詳細パネルが開く。件数は「完了した数」ではないので主役にしない。1 件の中央値の母集団は詳細パネルと同じ（clip 済み・`auto_migrated` を除く）
- 時間帯の分布（1 時間刻み）と 1 件の長さの分布も時間の使い方に出す（2026-09-15 User 指示）。多い時間帯は「集中できる時間」ではなく、1 件の長さは作業の完了に要る時間ではない。評価の言葉を添えない
- 前期間比は「今見えているアクティビティ」だけで足す（フィルタを掛けたまま期間を比べる）。前期間に記録が 1 分も無ければ差を作らない。増減は矢印と符号だけで示し、良し悪しの色を付けない
- 時間の表記は `28時間40分` / `12分`（`formatReportSpan`）。`h:mm` は `0:12` が 12 分に読めないため、この面では使わない
- 配置は広い幅で上段にカード 3 枚、下段 2 列（左 = 日ごとの記録時間・一覧、右 = 配分・2 つの分布）。狭い幅では 1 列に積み、一覧の件数・中央値の列と日別の列ごとの合計を落とす
- 「差分」に「レビュー」を付けない（用語集の禁止語）。「振り返り」はページ名と同じ語

各面のクリック先は 2 通りだけ:

- 行・点 → **詳細パネル**（デスクトップ）/ **ボトムシート**（モバイル）
- それ以外 → 無い

### 1 章の分母

`period.lengthMinutes` が期間そのものの長さ（週 = 10080 分）。

| 記号             | 実装              | 定義                                                 |
| ---------------- | ----------------- | ---------------------------------------------------- |
| `totalAll`       | `totalAllMinutes` | **フィルタを無視した**全アクティビティの記録合計     |
| `margin`（余白） | `marginMinutes`   | `lengthMinutes − totalAll`。**フィルタで動かない**   |
| `V`              | `visibleMinutes`  | フィルタを通した記録合計（見えているインク）         |
| `track`          | `trackMinutes`    | 配分の分母。`V` そのもの（0 除算を避けるため最小 1） |

**`computeDenominators` の `allActivities` にだけフィルタを掛けてはいけない。** 掛けるとカテゴリーを 1 つ隠しただけで余白の値が動き、「書かなかった時間」ではなく「表示の副作用」になる。カテゴリーを隠して動くのは `V` と `track` だけ。

**余白は配分に混ぜない。** 記録時間のカードに「余白 x」と小さく添えるだけで、区画も持たない。以前の「週 = 168h を分母にした決算バー」と、余白を分母から外す切替は 2026-09-15 に廃止した（切替は効くのが 1 面だけでサイドバーの出し入れと意味が違い、168h 分母は「意図に照らして読む」比率にならないため）。

## 2. フィルタ

サイドバー（デスクトップ）とフィルタの Drawer（モバイル）は**同じ `useReportViewStore`**（端末ローカル、persist v2）を読み書きする。フィルタは分析のためだけの一覧で、作成・編集・並び替え・アーカイブの口は持たない。

- **骨格・余白・ホバーはカレンダーのサイドバーが正本**。「カテゴリ」「未分類」の 2 見出し（どちらも折りたためる）、カテゴリー見出しの下に配下のアクティビティ、未分類見出しの下に未分類のアクティビティを平らに並べる
- **出し入れは行の右端の 👁**。見えている行の 👁 は行ホバーで出し、外した行は常時出す（戻す手段を隠さない）。行クリックでも切り替わる。カテゴリー見出しの行クリックは開閉
- **状態**: `hiddenCategoryIds` / `hiddenActivityIds`。hidden で持つので、新しく作ったカテゴリー / アクティビティは自動で分母に入る
- **カテゴリーの 👁**: 全部見えている → カテゴリーを外す / 一部外している → 配下の個別 hidden を解く / 外している → 戻し、配下の個別 hidden も解く。一部外している間は 👁 を常時出す
- カテゴリーを外している間に配下の 👁 を押す → カテゴリーを戻し、兄弟を個別に外す（その 1 行だけが見える）
- **未分類は見出しに出し入れの口を持たない**（カレンダーと同じ）。未分類のアクティビティは 1 行ずつ出し入れする
- **アクティビティ未設定の記録はフィルタ行を持たず、常に数える**（activities 仕様の「アクティビティなし」と同じ）
- **モバイルはタブ行の右端のボタンから同じ一覧を Drawer で開く**（`ReportFilterDrawer`）。中身は `ReportFilterList` そのもので、アクティビティ単位の出し入れもモバイルにある。何かを外している間はボタンに点が付く

**セグメントは 2026-09-15 に撤去した。** アクティビティ単位のフィルタで「この数個だけで見る」が足りるため、別概念を持たない。UI / tRPC / MCP の `segments.list` を消し、`segments` / `segment_activities` テーブルだけが残る（drop は不可逆なので別変更）。v1 の localStorage に残る `segmentId` / `uncategorizedHidden` / `marginHidden` は v2 への migrate で捨てる。

## 3. 閾値（沈黙の規則）

数えるに足りない回数で比率を作らない。定数は `domain/report/report-view-model.ts` にある。

| 定数                         | 値    | 効き方                                                                       |
| ---------------------------- | ----- | ---------------------------------------------------------------------------- |
| `EXECUTION_MIN_PLAN_MINUTES` | 15 分 | 2 章の予定比。過去予定がこれ未満なら `null`（0% でも空文字でもなくダッシュ） |
| `MIRROR_MIN_PLAN_MINUTES`    | 30 分 | 見積もりの鏡の候補条件                                                       |
| `MIRROR_MIN_PLAN_BOXES`      | 3 件  | 同上                                                                         |
| `COMPASS_MIN_FULFILLMENT`    | 5 件  | 羅針盤の点。充実の回答がこれ未満なら点にせず待機リストへ                     |

- **見積もりの鏡**: 「過去予定 >= 30 分」∧「記録がある」∧「過去予定の件数 >= 3」を**すべて**満たす行だけが候補。`|coef − 1|` の降順（癖の強い順）で最大 3 件。`coef = rec / planPast`。全体遵守率のような合成値は作らない
- **`planPast`** は開始が `nowAt` 以下の予定だけを数える。未来の予定で係数を汚さない
- **2 章の行は足切りしない**。記録か予定のどちらかがある行はすべて出す（決算の完全性）

## 4. 期間と URL 契約

- `/report?date=YYYY-MM-DD&range=week|month|year&tab=usage|diff|reflect`
- `range` の省略・不正値・旧 `day` は **`week` へ丸める**（`parseReportRangeParam`）
- `tab` の省略・不正値は **`usage` へ丸める**（`parseReportTabParam`）。既定タブでは `tab=` を書かない（`buildReportHref`）
- **デスクトップのタブはヘッダーの下の 2 行目**に置く。期間（ヘッダー）と面（タブ）を別の行で読ませる（2026-09-15 に一度ヘッダーの右端へ入れ、同日 User 指示で 2 行へ戻した）
- タブの切替は押した瞬間に面を変え、URL は `router.replace` で書く（履歴に積まない）。粒度の切替はタブを保つ
- 期間の正本は `/report` 自身の `date` と `range`。カレンダーの view とは独立している
- 表示中の日付は `CalendarNavigationContext` が URL から読んで保持する。**server component の prop で受け取らない** — `navigateToDate` は `history.replaceState` を書くだけで RSC を再描画しないため、prop を正本にすると `‹ ›` を押しても画面が変わらない
- 期間の移動は必ず `useCalendarNavigation().navigateToDate(date, true)` 経由。`navigateRelative` は使わない（カレンダーの viewType 基準で動くのでレポートの粒度と食い違う）
- 週の開始は `user_settings.week_starts_on`（0 / 1 / 6。土曜始まりもある）
- 期間を移したら詳細パネルは閉じる。別の期間の明細を開いたまま残さない。**タブの切替では閉じない**

## 5. 集計の分割

**server は 1 期間 1 round trip の「アクティビティ別スカラー集計」だけ返す**（`review.getReportPeriod`）。フィルタ・分母・鏡・羅針盤の派生は client の純粋関数（`features/review/domain/report/`）が導出する。カテゴリー / アクティビティのトグルとタブの切替でサーバーへ往復させない。

**タイムブロックの明細は主 payload に載せない。** 各タブに要るのは、アクティビティごとの件数（`plannedPastBoxes` / `recordBoxes`）・充実の回答数・0〜23 時の記録（`byHour`、24 個）・1 件の長さの度数（`durationCounts`、`[長さ, 件数]`）で、どれも Record 件数に比例しない。度数は「異なる長さの数」に比例するだけで、見えているアクティビティを client で合算すれば、どのフィルタでも全体の中央値と分布が正確に出る（中央値の中央値は中央値にならないため、スカラーの中央値だけでは足りない）。前期間も記録時間・件数・度数を返す。明細が要るのは詳細パネルだけなので、開いた時に `review.getReportActivityDetail` で取る。年粒度で payload が Record 件数に線形比例するのを構造的に断つ。

集計は**半開区間 + clip** で書く: `start_at < end AND end_at > start` で選び `[max(start, S), min(end, E))` へ clip する（#2426 の canonical query）。0 時またぎの記録は日別インクへ按分する。

置き場は `features/review/server/`（review が spec を所有する）。旧 `statistics-fetchers.ts` 経路は kpi / MCP が使うもので、レポートは通らない。

## 6. 詳細パネル / ボトムシート

行・点から開く。**中身は器によらず同じ**（`ReportDetailBody`）:

統計 4 枚（記録合計 / 予定との差 / 1 件あたりの中央値 / 充実の分布）→ 見積もりの鏡 → 1 件あたりの長さの分布 → 時間帯の分布（朝・午前・昼・午後・夜・深夜の 6 バケット）→ 週別の推移 → 明細。

- **1 件あたりの長さの分布**は 1 本の軸に、各記録の点・25〜75% の帯・中央値の線・**開始済み予定の中央値**（▲）を重ねる。点を押すと明細の該当行へ着地する。3 件未満は分布を作らず沈黙する（§0 の統計の誠実さ）
- **中央値系（カードの中央値・分布の点・推移の中央値）は `source = 'auto_migrated'` を除く**。自動移行はユーザーが確定した実績ではないので代表値に数えない（作成面の「普段の長さ」と同じ規則）。合計・充実・時間帯・明細は実際に埋まっていた事実なので全件を数える
- **週別の推移**は棒が合計、重ねた線が 1 件あたりの中央値。中央値の無い期間で線を切る（0 として谷を描くと「短くなった」と読めてしまう）
- **編集はしない**（充実の後付けは編集面の仕事）。カレンダーへの導線は明細行だけが持つ（§7）
- **「（記録中）」は作らない**。Dayopt の Record は常に `end_at <= now` で、記録中という状態が存在しない
- 明細の時刻・曜日とジャンプ先の日付は、ブラウザのローカルではなく**ユーザー設定の timezone** で切る
- 器は Composition Bridge が選ぶ。**デスクトップ** = shell の 4 カラム目（既定 360px・左端のドラッグで 250〜560px）へ portal、**モバイル** = `Drawer`
- store（`useReportDetailStore`）は shell の 4 カラム目の開閉も握っているので、`/report` を離れる時に閉じる（中身の無い帯を他ページへ持ち越さない）

## 7. カレンダーへのジャンプ

ルーティングは review が持たない。Composition Bridge（`_composition/useReportJump.ts`）が担い、review は props のコールバックで受ける。

| 導線                     | 飛び先                                               |
| ------------------------ | ---------------------------------------------------- |
| 詳細パネルの明細行を押す | その Record の日を日ビューで開き、その Record を選択 |

旧 4 章の 3 導線（未分類の記録を仕分ける / 未変換の外部予定を見る / 次の期間を開く）は 2026-09-15 に撤去した。

## 8. モバイル

**計算はデスクトップと完全に同一**（§10 の 13-13）。器だけが違う。

**出さないもの**:

- 粒度切替 UI（狭い面で期間ラベルと `‹ ›` が潰れる）
- 詳細シートの週別推移（`includeTrend: false` で**取得ごと**落とす。表示側だけで落とすと運ぶだけ無駄になる）

**出すもの**: 期間ラベルと `‹ ›`（`ReportMobileHeader`）、タブとフィルタのボタンを同じ行に（`ReportTabs` + `ReportFilterDrawer`）、詳細のボトムシート。ヘッダー → タブ行 の 2 段で本文が始まる。

**粒度そのものは URL を尊重する。** `?range=month` をスマホで開いたら月のまま描く。デスクトップで月を見て共有したリンクが壊れないほうを選ぶ（2026-09-05 User 裁可）。§8 の「週固定」は「切替 UI を出さない」の意味に取る。

**スワイプ**で前後の期間へ動く: `|dx| > 55px ∧ |dx| > 1.4 × |dy|`。`/report` は縦スクロールが主なので、章をなぞる指で数字が黙って入れ替わらない値にしてある。移動は §4 のとおり `navigateToDate` 経由。

**面の判定の正本は shell（`BaseLayoutContent`）と同じ `MEDIA_QUERIES.mobile`**（幅のみ）。`useIsMobile()`（幅 **かつ** coarse pointer）を使ってはいけない — 狭くしたデスクトップの窓で shell は `MobileLayout`（詳細の DOM slot 無し）を描くのに中身は desktop 扱いになり、フィルタのボタンが出ないうえ行を押しても何も開かない面が生まれる。

## 9. やらないこと

実装禁止リスト（要望が来ても入れない）:

- 合成スコア・ストリーク・カバー率・目標バー・達成率
- 充実の平均値 / 5 段階化 / 色分け / 絵文字
- 羅針盤の平均・回帰線・象限の塗り分け・ランキング
- ウィジェットのカスタマイズ、日単位の分析ビュー
- 円グラフ
- レポート面での作成・編集、週の締め・ロック
- 他人との比較、通知・催促文言
- 余白を灰色の区画で塗ること

## 10. 実装の不変条件

- **13-2**: `computeDenominators` の `allActivities` にフィルタを掛けない（§1 の分母を参照）
- **13-13**: **モバイル専用の集計を作らない**。器が違うだけで、分母もフィルタも 1 つの真実（同じ store・同じ純粋関数）に集約する
- **依存の向き**: `features/review → lib/`。review は同層の `features/calendar` を import できない。共有したい hook は `lib/hooks/` へ置く（`useSwipeGesture` がそれ）
- **query は Composition Bridge から**。tRPC query を持つ component を `ReportBody` の中へ入れない（`/report` 以外から描いた時に context を要求してしまう）
- component の visual state は Storybook（`Product/Features/Review/...`）、集計の data flow と composition は [Engineering Architecture](../../engineering/architecture.md) を参照する
