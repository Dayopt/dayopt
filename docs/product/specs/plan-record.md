# Plan / Record（予定 / 記録）

Dayoptの中心概念。「予定を立てる → 記録する → 差分を見る」のループを、Plan（予定）と Record（記録）の2エンティティで表現する。旧 Entry 単一モデル（計画・実績を1行で持つ）は ADR-025 で廃止した。

## 保存モデル

- 予定は `plans`、記録は `records` に独立した行として保存する。相互参照・実行状態は保存しない。
- 所有者、監査日時、論理削除、外部カレンダー参照、Undo の操作対象 ID は保持する。
- `source = 'from_plan'` は作成経路だけを表し、対応先や実行状態を表さない。
- 片側の移動・伸縮・アクティビティ変更・削除・復元は、相手側の保存列と更新日時を変更しない。

## 新規作成時の保存先ルール（選択 UI なし）

- 新規作成時は **`end_at > now` → Plan、`end_at <= now` → Record** とし、時間範囲だけで保存先を決める
- 詳細 Inspector では開いた Plan / Record の種別を維持し、時間編集による暗黙変換はしない
- Plan から Record を作る場合は「そのまま記録」などの明示的な記録導線を使う
- エディタは Plan / Record で共有し、日時とメモを編集する

## 見積もりフィードフォワード（作成時）

- 保存先が Plan の draft 編集時にだけ、選択した activity の直近実績を「このアクティビティの直近の記録は {duration} 前後です」と示す。日時グルーピングの直上にバッジとして置く（時間を決める前に目に入る位置。2026-09-10 に本文へ紛れる 1 行から改めた）
- 強めるのは配置と形だけで、警告色・アイコン・感嘆符は引き続き使わない（ADR-026）
- 表示条件は、選択したアクティビティについて直近28日の過去予定3件以上、経過済み予定15分以上、記録時間が正であること。
- 係数は期間内の記録合計 ÷ 経過済み予定合計。予定ごとのペアや比率中央値は使わない。下書きの長さへ掛け、既存の5分刻み・下限5分に丸める。
- 値はユーザーの入力を書き換えない。読むかどうかはユーザーに委ねる

## 普段の長さ（記録の中央値）

- アクティビティ選択の一覧では、各行の名前の後ろにそのアクティビティの**記録の長さの中央値**を「45m」のように添える。予定・記録どちらを作る時も同じ値を出す（実際にかかった時間が目安になる）
- 集計はテンプレート適用が着せる長さと同じ定義を使う。直近 28 日・記録 3 件以上・5 分丸め・`source = 'auto_migrated'` は除外。窓の境界に跨る記録は切り詰めず実際の長さで数える
- 記録が 3 件に満たないアクティビティでは何も出さない（沈黙する）。警告色・アイコン・感嘆符は使わない
- ドラッグ作成では、一覧のアクティビティにホバーした時点でその長さを選択範囲へ着せる。グリッドのハイライトの厚み・パネルの時刻・重なり判定・作成される長さは同じ 1 つの値を読むので食い違わない。ホバーを外す / 中央値の無いアクティビティへ移ると、ドラッグで決めた長さへ戻る
- ただしユーザーがリサイズや時刻入力で長さを直した後は着せない。ドラッグは「どこに置くか」だが、リサイズ・時刻入力は「どれだけの長さにするか」の明示指定なのでそちらが勝つ
- サイドバー / チップ行のタップからの即作成も、この中央値を長さに使う。中央値が無ければ設定の既定の長さへフォールバックする。保存先は従来どおり `end_at` のルールで決まる
- タップした時間が同じレーンで埋まっている時は作成を止めず、その日のうちで長さが丸ごと入る最初の空きへずらす。長さは縮めない。ずらした時は作成した時刻をトーストで知らせる。その日にもう入らない時だけ、作らずに知らせる
- サイドバーのアクティビティ行には数字を出さない（行はテキストのみの規律を保つ）

## 詳細 Inspector の保存

- 保存ボタンは表示しない
- アクティビティは選択の確定時、日時は編集可能な状態で有効な日付・開始・終了が確定した時に自動保存する
- メモは入力停止から600ms後に自動保存し、フォーカス解除または Inspector を閉じる時は待機中の内容を即時保存する
- 更新は直列に実行し、保存待ちの変更は最新値へまとめる。自動保存中も入力を無効化しない
- 「そのまま記録」は表示中のアクティビティ・メモを保存キューの末尾で確定し、その保存に成功してから Record を作る。保存失敗時は記録しない
- 過去 Plan も日時を含め通常どおり編集できる（凍結しない）

## 詳細 Inspector の時間帯表示

- 予定詳細の「この時間帯の記録」は、同じアクティビティで実際に15分以上重なる記録を表示する。未設定同士は同じグループとする。
- 表示対象は毎回導出する。記録の移動・アクティビティ変更に応じて変わり、予定全体の完遂を意味しない。
- 記録詳細に「元の予定」は持たない。予定詳細から記録を選ぶと同じ Inspector 内で開く。
- 「そのまま記録」は終了済み予定の内容を独立コピーする。同時間帯の競合は既存の記録レーン制約で拒否する。

## Calendar カードの表示名

- Plan / Record カードの表示名はアクティビティ名を source of truth とする
- DB 互換の `title` はカード表示へフォールバックしない。アクティビティがない、または解決できない場合は「アクティビティなし」と表示する
- アクティビティ名は都度アクティビティ本体から解決し、改名をカード表示へ反映する。表示色は所属カテゴリーから継承する（[activities.md](./activities.md)）
- 詳細 Inspector は `title` 入力を表示せず、アクティビティを表示名として編集する

## 記録操作と表示

- 「そのまま記録」はアクティビティ・開始終了・メモを新しい記録へコピーする。予定は残り、更新しない。
- 記録レーンへのドラッグはプレビュー範囲の独立記録を作る。
- 「この日を確定」は終了済み予定のうち、既存記録と少しでも重なる予定を丸ごと除外する。トリムしない。ユーザー単位の直列化とトランザクションを維持する。
- 記録を移動して元の時間帯が空けば再度コピーできる。
- 手動の skip 操作は廃止。以前の該当予定も残存する予定として集計する。
- カレンダーはアクティビティに関係なく、時間が少しでも重なる予定・記録を左右に表示する。15分閾値は配置には適用しない。
- 個々の予定と記録を対応付けた差分バッジは表示しない。

## 共通導出

`apps/product/src/lib/time/derived-model.ts` の `overlappingRecords` と `aggregate` が正本。保存型とは別の読み取り型を使う。

- 期間は `[startAt, endAt)` とユーザーのタイムゾーンで指定する。週の開始日は既存設定から解決する。
- 記録・予定は期間との交差時間を計上する。経過済み予定は終了を `min(end, now)` で切り、負の時間を計上しない。
- 予定比と見積もりの鏡は記録時間 ÷ 経過済み予定時間。分母15分未満は「—」。同一期間内の移動では比率は変わらない。
- 日別集計は日境界で按分し、DSTを含む実際の経過時間を使う。保存行は分割しない。
- 記録明細・充実度回答は元の記録1件につき1件。中央値は期間内に切り詰めた記録の長さから算出する。
- 提案（`gh`）は除外。読み取り型の実行中記録は終了を `now` とする。DBの記録は `live: false`。
- 取得は所有者・論理削除・時間重複を絞り、ページを最後まで取得する。サマリーは集約値だけを返す。

## コピー / 貼り付け

- 詳細 Inspector とカードの右クリックにある共通の `…` メニューからコピーできる。選択中は `Cmd/Ctrl+C` でも同じコピー状態を作る
- コピー対象は Plan / Record の種別、アクティビティ、メモ、開始時刻、長さ。元の `id` は引き継がず、貼り付け先には独立した新規行を作る
- `Cmd/Ctrl+V` はコピー元の種別を維持する。Plan は任意の日時、Record は過去にだけ貼り付けられ、条件外では種別を暗黙変換せずエラーを表示する

## Inspectorの時間編集

- 時刻入力が確定した時点で、query cacheにある同一レーンのブロックとの重複を判定する。Plan同士・Record同士だけを禁止し、PlanとRecordの相互重複は許可する
- 編集中のブロック自身は重複判定から除外する。隣接する半開区間は重複にしない
- 重複時は日時入力をエラー表示にし、直下に`TimeConflictAlert`を表示して自動保存を行わない。空き時間へ変更するとエラーを解除して保存する
- client判定は応答速度のためのbest-effortであり、cache外の行と同時更新に備えてserver validationを正として維持する。serverが重複を拒否した場合も同じインラインエラーを表示する

## 複製

- 詳細 Inspector とカードの右クリックにある共通の `…` メニューから、Plan / Record の両方を複製できる
- 複製を選ぶと同じ Inspector に未保存の詳細カードを表示し、アクティビティ、メモ、所要時間、Plan / Record の種別を引き継ぐ
- Plan は任意の日時、Record は過去の時間だけを受け付け、種別を暗黙変換しない
- 作成時に同一レーンの既存ブロックと重複した場合は行を作らず、サイドバーのアクティビティ作成と同じ `TimeConflictAlert` を日時入力の直下に表示する。重複トーストは出さず、日時を変更するまで作成を無効にする
- 複製下書きは自動保存せず、「複製を作成」で独立した新規行を作る。元の `id`、外部カレンダー関係は引き継がない
- キャンセル時は新規行を作らず、元ブロックの詳細へ戻る

## DB 契約

物理 DB、正本 RPC、生成型は Record に統一済み。テーブルは `records`、一括確定は `confirm_day_plans_to_records`、soft delete / restore は `soft_delete_record` / `restore_record` を使う。旧 `logs` view と Log 名 RPC alias は存在しない。

## 時刻の規則（2本だけ）

Plan / Record を通じて強制点は2本だけで、これ以外に過去・未来で操作を出し分けない（2026-09-04 に「未来 Plan」向けの特例4種を撤去した）。

| 規則                                         | 対象          | 強制点                                                    |
| -------------------------------------------- | ------------- | --------------------------------------------------------- |
| `end_at > start_at`                          | Plan / Record | DB trigger（`DT003`）                                     |
| Record は未来に終われない（`end_at <= now`） | Record        | DB trigger `validate_record_temporal_write_v1`（`DT005`） |

| 操作                                   | 可否                                                                    |
| -------------------------------------- | ----------------------------------------------------------------------- |
| 過去 Plan の時間変更（移動・リサイズ） | ○（編集しても Plan のままで、Record へは変わらない）                    |
| アクティビティ・メモの訂正             | ○                                                                       |
| 過去日付への新規 Plan 追加             | ✗（新規作成の宛先は `end_at` のみで決まり、過去日時なら Record になる） |
| ワンタップ記録 / 削除                  | ○                                                                       |

Record は終了が現在以前の範囲で、時間・アクティビティ・メモを訂正できる（終了を未来へ動かす編集だけ不可）。

## 重なり制約

- Plan 同士・Record 同士: EXCLUDE 制約で禁止（半開区間 `)`、per-user、`deleted_at IS NULL` のみ対象）
- Plan × Record: 許可（予定と記録は別レイヤーなので重なってよい）
- Plan を Record レーンへドラッグする時は、ドロップ範囲を既存 Record と照合する。Plan との重なりは拒否理由にしない
- 緩和は実質不可逆（一度重なりデータが入ると再強化にデータ犠牲が伴う）
