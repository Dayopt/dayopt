# 競合ポジショニング

Dayopt が競合とどう違い、何を監視するかの正本。調査の詳細（各社プロファイル・価格表・ERRC・機能マトリクス）は時点ものとして log に置く:

- 競合機能マトリクス snapshot（2026-03 調査）（削除済み、git 履歴参照）
- 競合深掘り調査（2026-06-15）（削除済み、git 履歴参照） — 個別競合の詳細メモ

カテゴリとコアメッセージの言い方は [strategy.md §2](../strategy.md) を正とする（「いちばん軽いタイムボクシングツール」/ "Plan days you can actually keep."）。

## ポジション（2軸マップ）

```
          効率重視（Do More）
               ↑
               |
  Motion ◉     |     ◉ Reclaim
               |
  Akiflow ◉    |     ◉ Morgen
               |
自動化 ←———————+———————→ 手動制御
               |
      Amie ◉   |   ◉ Sunsama
               |
               |  ◉ Structured
               |
               |        ★ Dayopt
               ↓
          認識重視（See Clearly）
```

- 横軸: 時間配分を AI が決めるか、ユーザー自身が決めるか
- 縦軸: ゴールが「より多くこなす」か「自分の時間の使い方を理解する」か
- Dayopt は**手動制御 × 認識重視**の象限に唯一位置する。競合と value curve が交差しないため、機能の直接比較で戦わない

## Dayopt だけが勝てる 4 点

これらを 1 社でも揃えている競合は存在しない（2026-03 調査時点）。

1. **予定と実績の 2 レーン比較（Plan / Record）** — 意図と現実のギャップを同じタイムラインで可視化する。Sunsama の日次振り返りが最も近いが、同じ時間軸の 2 レーン UI ではない
2. **Emotional safety** — スコア・ストリーク・赤マーク一切なし。判定しないデザイン。Sunsama も「穏やかさ」を謳うがタスク完了率は追跡する
3. **最小入力** — アクティビティが語彙、タイトル欄なし。3 ステップで予定が立つ（[strategy.md §4-1,2](../strategy.md)）
4. **$5/月 + Free 枠** — 競合の 1/4〜1/6。Free 枠ありは 8 社中 3 社のみ

## 意図的に戦わない 5 点

「できない」ではなく「やらない」。追加すると何が壊れるかまで含めて確定済み。

| 競合の強み             | 戦わない理由                                               | もし追加したら何が壊れるか                                     |
| ---------------------- | ---------------------------------------------------------- | -------------------------------------------------------------- |
| AI自動スケジューリング | ユーザーが自ら配分を決める行為こそがタイムボクシングの本質 | 「自分で決める」感が消え、Motionの劣化版になる                 |
| タスク管理             | 「いつ・どれだけ」のレイヤーに集中。「何を」は別ツール     | ブロック情報密度が上がり、アクティビティ中心入力の簡潔さが崩壊 |
| チーム機能             | 個人の鏡。他者に見せないからこそ本音の配分ができる         | 「見られている」意識がデータの正直さを損なう                   |
| Meeting intelligence   | 会議管理ではなく、会議に「配分した時間のパターン」を見る   | プロダクトの焦点がカレンダー機能に引きずられる                 |
| 30+のIntegration       | 統合競争に入らない。連携は MCP/API と外部カレンダーの 2 点 | 外部データのノイズがシグナルを希釈する                         |

- 外部カレンダーは調査当時「未実装・Phase 2 検討」だったが、現在は**ゴースト経由の取り込みとして採用済み**（[strategy.md §4-3](../strategy.md)）。これは統合競争入りではなく、配分の文脈を得るための最小連携
- AI も同様に in-app では作らず（[strategy.md §4-8](../strategy.md)）、MCP / API でユーザー自身の AI に開く

## 監視すべき動向

| 競合           | 監視ポイント                            | 脅威度 | トリガー                                          |
| -------------- | --------------------------------------- | ------ | ------------------------------------------------- |
| **Sunsama**    | emotional safety 方向への舵切り         | 高     | 「判定しないプランナー」ポジション宣言            |
| **Structured** | Pattern discovery / Record layer の追加 | 高     | 価格帯 × ミニマリズム × タイムラインUIが3軸で競合 |
| **Motion**     | B2C特化の低価格プラン                   | 中     | AI自動化 vs 手動配分の価値観対決                  |
| **Reclaim**    | Dropbox統合でB2C回帰                    | 低     | エンタープライズ方向に進む可能性のほうが高い      |
| **新興**       | Plan + Record overlay を持つ新規参入者  | 中     | Dayoptの核心機能をコピーされるリスク              |

## 更新の運用

- 価格・新機能の再確認は、競合比較が必要になった時に行う（owner 不在の定期チェックリストは持たない）
- 個別競合の深掘りが必要になったら `log/YYYY-MM-DD-competitor-research-<name>.md` を追加し、本ファイルには結論（ポジション・監視トリガーの変化）だけを反映する
