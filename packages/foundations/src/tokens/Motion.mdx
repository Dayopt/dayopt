# Motion & Feedback（モーションとフィードバック）

**このファイルがモーション方針の正本。** duration / easing の段階表を他の場所に複製しない。

体験の目標は「紙のスケジュール帳の安心感」と「デジタルの明快さ」の両立。**chrome は退き、データが主役**という原則（[Colors](?path=/docs/shared-foundations-colors--docs) と同じ）をモーションにも適用する。

---

## 原則: 応えるが、褒めない

「圧をかけない」と「モチベーションを支える」は対立しない。ストリークやバッジのような外発的報酬は、記録という内発的動機を侵食する（報酬が目的化し、途切れると行為ごと止まる）。紙の手帳が続くのは**埋まったページそのものが報酬**だから。Dayopt はこちら側に立ち、デジタルの利点は「その報酬をより速く、より明快に見せること」に使う。

判定基準はひとつ。**記録が完成した事実を認めるのはよい。ユーザーを評価・採点するのはしない。**

---

## 4層の応答方針

開発者は duration を選ばない。**「この操作はどの層か」だけを決め、値は層が持つ。**

| 層         | 何に応えるか       | モーション                         | ハプティクス | トースト   | 頻度       |
| ---------- | ------------------ | ---------------------------------- | ------------ | ---------- | ---------- |
| **1 確認** | 全操作             | `duration-150` / `200` + settle    | `tap`        | なし       | 毎操作     |
| **2 蓄積** | 埋まっていく成果物 | `duration-300`（ビュー設計で出す） | なし         | なし       | 常時       |
| **3 距離** | 計画と実績のズレ   | なし（数字の更新のみ）             | なし         | なし       | レビュー時 |
| **4 温度** | 「揃った」瞬間     | settle 1回                         | `impact`     | 事実の記述 | 1日1回程度 |

### 層1 — 確認（acknowledgement）

全操作に即座・静かな応答を返す。「ちゃんと受け取った」とは応えるが、褒めない。

- 150〜250ms、バウンスなし
- 遅延や曖昧な状態遷移は「静か」ではなく**不安**。応答性能を世界観の一部として扱う
- 例: タイムブロック配置時の `animate-timeblock-settle`、hover / focus の色変化、モバイルの `tap`

### 層2 — 蓄積の可視化

進捗感は演出ではなく**成果物自体の変化**で出す。1日が記録で埋まる、週表示で並びが整う。演出を足すのではなくビューの設計で報酬を作る。

### 層3 — 計画と実績の距離

達成率で評価しない。計画と実績を並べて距離を見せるだけ。**この層に演出が無いのが要点**で、評価しないので褒める対象がない。継続は「21日分の記録があります」と**記述**する。途切れリセットで喪失感を作るストリーク型にはしない。

### 層4 — 温度の一滴

感情的なフィードバックは「揃った」瞬間だけに限定する（1日の記録の完成、週次レビューの完了）。静かな settle と、事実を述べる文言。文言は [copywriting.md](https://github.com/Dayopt/dayopt/blob/main/docs/product/copywriting.md) に従う。

## 禁止リスト

| 禁止                                     | 理由                                     |
| ---------------------------------------- | ---------------------------------------- |
| confetti / パーティクル                  | 達成を祝う演出。層4 の頻度にも収まらない |
| バウンス / スプリング / オーバーシュート | 物理的な誇張。「静か」から外れる         |
| 効果音のデフォルト ON                    | 環境を選べない                           |
| ストリーク型のリセット                   | 途切れで喪失感を作り、行為ごと止める     |
| バッジ / スコア                          | 外発的報酬が内発的動機を侵食する         |
| 未達を赤字・警告色で責める               | ズレは事実であって失敗ではない           |

> 2026-07-30 に、タイムブロック新規作成時の花びら演出（8枚・550〜620ms）を廃止した。実質 confetti で、層1 の予算を 2.5 倍超え、毎回の作成で発火していた。`animate-timeblock-settle`（200ms）に置き換えた。

## トークン

値の実体は `tokens/motion.css`。

### 遷移・一過性

**Tailwind v4 には `--duration-*` の theme namespace が無い**（v4.3.3 で実測確認）。そのため長さは Tailwind 組み込みの数値ユーティリティをそのまま使う。spacing / font-size と同じ扱い。

| クラス         | 用途                                   |
| -------------- | -------------------------------------- |
| `duration-150` | **標準**。色・状態の変化。ほぼ全てこれ |
| `duration-200` | transform・位置の変化、一過性の着地    |
| `duration-300` | 大きい面の開閉（sheet, accordion）     |

この3段以外は使わない。任意値（`duration-[420ms]`）も使わない。

### 持続（loop）

状態を示し続けるループ。CSS の `animation` から参照する。**遷移と混ぜない** — 遅いこと自体が正しい。

| 変数                    | 値     | 用途                          |
| ----------------------- | ------ | ----------------------------- |
| `--motion-loop-shimmer` | 1500ms | skeleton の光沢、不定進捗バー |
| `--motion-loop-breath`  | 1600ms | 実行中エントリの呼吸          |

### Easing

`--ease-*` の namespace は存在するので、easing はトークン化してユーティリティにしている。

| クラス          | 変数                     | 用途                                 |
| --------------- | ------------------------ | ------------------------------------ |
| `ease-standard` | `--motion-ease-standard` | その場で変わるもの（色、状態、退出） |
| `ease-settle`   | `--motion-ease-settle`   | 入ってくる・着地するもの             |

**2種だけ。** 減速して止まるのが物理で、紙の質感に合う。等速で止まると機械的に見える。退出も `standard` を使い、exit 専用の easing は持たない（判断を増やさないため）。

禁止 easing クラス（`ease-in` / `ease-out` / `ease-in-out`）は **theme をリセットしてあるので生成されない**。書いても easing が付かないだけで、見た目が静かに崩れることはない。`ease-linear` だけは Tailwind の組み込み（CSS キーワード `linear`）で theme のリセットに影響されない（`rounded-none` と同じ扱い）。

`cubic-bezier` をコード側に直書きしない。

## 例外

3段に収まらないが、意図があって残しているもの。増やす時はここに書く。

| 箇所                           | 値    | 理由                                                           |
| ------------------------------ | ----- | -------------------------------------------------------------- |
| `--motion-oneshot-shake`       | 400ms | 振動を振動として知覚させるには往復が要る                       |
| `GhostRenderer` のドラッグ追従 | 50ms  | 状態遷移ではなくポインタ追従の平滑化。伸ばすとドラッグが遅れる |
| `animate-caret-blink`          | 1.25s | tw-animate-css 由来。OS のカーソル周期に近い                   |

## マーケティングサイト（apps/web）はアニメーションを持たない

2026-07-30 に `apps/web` の装飾アニメーションを全廃した。当初は「LP の演出はプロダクト UI と目的が違う」として例外扱いにしていたが、そもそも不要と判断した。

削除したもの:

| 削除                                | 内容                                            |
| ----------------------------------- | ----------------------------------------------- |
| `hero-animate` + `hero-delay-1..10` | 見出しを単語ごとに 0〜1500ms でずらして出す演出 |
| `hero-glow-breathe`                 | 見出し背後のグローを 4s で拡縮                  |
| `hero-cta-attention`                | 1.5s 後に CTA を 1 回光らせて注目を引く         |
| `hero-cta-glow`                     | CTA の hover グロー                             |
| `animate-shake`                     | apps/web では未使用だった                       |

残したもの:

- `animate-shimmer` — 装飾ではなく「読み込み中」という状態表示
- `hero-ambient-glow` — アニメーションを外した静的なグローだけ
- `hero-carousel-scroll` — スクロールバー非表示。アニメーションではない

`hero-cta-attention` は特に、issue #1762 が避けるとした「ギラギラした生産性アプリ感・達成圧」に最も近い実装だった。時間差で光って注目を引く CTA は、寡黙な研究者のトーンから最も遠い。

## prefers-reduced-motion

`tokens/motion.css` の全体規則が product と web の両方に効く。`animation-duration: 0.01ms` と `animation-iteration-count: 1` を `*` にかけるので、**無限ループも含めて個別クラスの列挙は不要**。

アプリ側に書くのは「止めると中途半端な見た目で固まるもの」への静的な代替だけ。

| 対象                | 代替                      |
| ------------------- | ------------------------- |
| `.animate-shimmer`  | 単色背景（`--container`） |
| fade / slide / zoom | 可視に固定（opacity 1）   |

## Do's & Don'ts

```tsx
// ✅ Do — 層1 の確認。既定の 150ms
<button className="transition-colors duration-150 ease-standard" />

// ✅ Do — 着地するものは settle
<div className="transition-transform duration-200 ease-settle" />

// ❌ Don't — 段階外の duration
<div className="transition-all duration-500" />

// ❌ Don't — 任意値
<div className="duration-[420ms]" />

// ❌ Don't — cubic-bezier 直書き
<div style={{ transition: 'transform 200ms cubic-bezier(0.25, 0.1, 0.25, 1)' }} />
```

## 何が自動で守られるか

`pnpm lint:tokens` が 4 つのモーション規約を検出する（禁止 duration / duration の任意値 / 生の easing / `cubic-bezier` 直書き）。

検出範囲は `apps/product/src` / `apps/web/src` / `packages/components/src` / `packages/foundations/src` の `*.tsx` + `*.ts`（`scripts/lib/check-tokens-core.ts` の `SCAN_TARGETS`）。**CSS ファイルは対象外**なので、そちらはこの文書とレビューで担保する。実際、2026-07-30 に是正した違反には CSS のもの（`calendar.css` の `cubic-bezier` 直書き）があり、lint では検出できなかった。
