# カラートークン

tokens/colors.css のセマンティックトークン一覧。Tailwind クラス名でそのままコピペ可能。

> **2層構造**: Primitives（原液） → Semantic（役割）。
> Hue定数やNeutralスケールは `src/styles/tokens/primitives.css` を参照。

---

## カラー判断フロー

新しいコンポーネントを作るとき、この 3 ステップでトークンを決める。

### Step 1: この面はどこにいる？（L軸 = 空間の階層）

問い: 「ユーザーの視線がここに集まるべきか？」

| 答え                                 | トークン        | 具体例                                        |
| ------------------------------------ | --------------- | --------------------------------------------- |
| ここは裏方、常にいるけど主役じゃない | `bg-container`  | sidebar、サイドパネル、footer、settings panel |
| ここが地面、基本の居場所             | `bg-background` | ページ全体、メインエリアの地                  |
| ここに注目してほしい、手前に浮く     | `bg-card`       | カード、dialog、popover、dropdown             |
| ここは入力を受ける窪み               | `bg-muted`      | input、textarea、well、badge の地             |

> 迷ったときの補助判断: そのコンポーネントを消したら「あ、なくなった」と気づくか？
> 気づくなら card（浮く）。気づかないなら container か muted（沈む）。
>
> shadow は [Elevation](?path=/docs/foundations-elevation--docs) で別途選ぶ。色の判断には含めない。

### Step 2: 色をつける必要があるか？（H軸 = 意味）

問い: 「この要素は状態や種別を色で伝える必要があるか？」

必要ないなら Step 1 で終わり。neutral のまま。surface と text のトークンだけで完結する。
**実際にはほとんどの UI がここで終わる。色は「意味がある場合だけ」つける。**

色が必要なら、意味で hue が決まる:

| 意味                   | トークン      | 色           | 使う場面                          |
| ---------------------- | ------------- | ------------ | --------------------------------- |
| アクション、リンク     | `primary`     | blue (H≈260) | CTA ボタン、リンク、ハイライト    |
| 注意、警告             | `warning`     | amber (H70)  | 警告バナー、注意喚起              |
| 成功、完了、ポジティブ | `success`     | green (H150) | 達成、+の差分                     |
| エラー、削除、危険     | `destructive` | red (H25)    | 失敗、-の差分、destructive action |

> `info` は neutral（グレー）。補足情報として区別したいが色で主張する必要がない場合に使う。
>
> 迷ったときの補助判断: 「この色を別の色に変えたら意味が変わるか？」
> 変わるなら semantic color を使う。変わらないなら neutral のまま。

### Step 3: どの強さで使う？（C軸 = 用途）

問い: 「この色はどのくらい主張すべきか？」

| 主張の度合い             | トークンパターン    | Tailwind クラス例                | 使う場面                                   |
| ------------------------ | ------------------- | -------------------------------- | ------------------------------------------ |
| 背景にうっすら敷く       | `{name}-tint`       | `bg-warning-tint`                | tint 背景、セクション背景                  |
| はっきり色として見せる   | `{name}` (accent)   | `bg-destructive`, `text-primary` | アイコン、border、progress bar、塗りボタン |
| 色のついたテキスト       | `text-{name}`       | `text-success`                   | ラベル、リンク、状態テキスト               |
| 色の面の上に乗るテキスト | `{name}-foreground` | `text-destructive-foreground`    | 塗りボタンの文字、badge のテキスト         |

> 迷ったときの補助判断: 「ここをグレーにしても機能するか？」
> 機能するなら `-tint`（控えめ）で十分。グレーだと意味が消えるなら accent（はっきり）にする。

### 全体をつなげると

```
新しいコンポーネントを作る
  │
  ├─ Step 1: この面はどこ？
  │    → container / background / card / muted
  │    （色なし。これだけで9割のUIは成立する）
  │
  ├─ Step 2: 色で意味を伝える必要ある？
  │    → No → 終わり。neutral のまま
  │    → Yes → primary / warning / success / destructive
  │    （info は neutral。色ではなくアイコン・テキストで伝える）
  │
  └─ Step 3: どの強さ？
       → 背景にうっすら → bg-{name}-tint
       → はっきり見せる → bg-{name} / text-{name}
       → 塗り面の上のテキスト → text-{name}-foreground
```

一番大事なのは、**Step 1 だけで終わるコンポーネントが大半**ということ。
色は例外的に足すもので、デフォルトは neutral。これを守るだけで画面がうるさくならない。

## Surface（3段階 + muted）

container(沈む) → background(基準) → card(浮く)。**Light は「紙」（warm H75, C=0.005）、Dark は warm H60, C=0.008。** 面はすべて同じ温度を持つ。

| トークン        | 役割   | Light (H75 C.005)      | Dark (H60 C.008)       |
| --------------- | ------ | ---------------------- | ---------------------- |
| `bg-container`  | 沈む   | `oklch(0.95 0.005 75)` | `oklch(0.15 0.008 60)` |
| `bg-background` | 基準   | `oklch(0.97 0.005 75)` | `oklch(0.18 0.008 60)` |
| `bg-card`       | 浮く   | `oklch(0.99 0.005 75)` | `oklch(0.22 0.008 60)` |
| `bg-muted`      | 控えめ | `oklch(0.94 0.005 75)` | `oklch(0.25 0.008 60)` |
| `bg-overlay`    | —      | `black / 0.32`         | `black / 0.50`         |

`bg-card` は純白ではない。L=1.00 では chroma を持てないため、card だけ純白に残すと 4 面のうち 1 面で色温度が割れる。純白が必要なのは「色地の上の文字」（`primary-foreground` 等）と QR コードのように読み取り精度が要るものだけ。

## Primary — 紺（インク）

| トークン                  | Light                 | Dark                 | 用途                 |
| ------------------------- | --------------------- | -------------------- | -------------------- |
| `bg-primary`              | `oklch(0.40 0.105 H)` | `oklch(0.55 0.13 H)` | 主要アクションの背景 |
| `text-primary-foreground` | `oklch(1 0 0)`        | `oklch(1 0 0)`       | Primary 上のテキスト |

H = `--hue-brand` (259.8145)。`ring` は primary 派生で自動追従する。

> Primary = 「ユーザーアクションを促す要素」にのみ使用する。
> ✅ CTA ボタン、リンク、フォーカスリング
> ❌ 装飾、待機状態の背景、大面積の背景

### なぜ紺なのか

旧値 `oklch(0.45 0.14)` = `#2051a1` は、伝統色の**瑠璃色** `#1E50A2`（L0.446 C0.143 H259.9）と誤差レベルで一致していた。瑠璃は宝石の青で、Dayopt が掲げるトーン（寡黙な研究者・実験ノートのインク）は**紺**（L0.36 C0.098）の側にある。そこで彩度を 25% 落とした。

**色相は動かさない。** 濃藍 H263.6 / 紺 H264.1 / 鉄紺 H276.3 と、深い藍はむしろ現状の H259.8 より上に集まる（H236.8 の藍色は明るい藍染めの色で例外）。色相を下げると藍から遠ざかる上に、`tag-blue`(H240) と `entry-default`(H220) に衝突して UI chrome とユーザーデータの色の区別が消える。

Dark で明度を上げている（0.50 → 0.55）のは、`primary-foreground` が白で白文字 4.5:1 を満たす上限が L0.55 だから。

## Semantic（bg + accent 体系）

destructive / warning / success は同じ L/C 構造で hue のみ変化。info は neutral（低彩度）。

| 色          | Hue     | Light accent           | Light bg                | Dark accent            | Dark bg                |
| ----------- | ------- | ---------------------- | ----------------------- | ---------------------- | ---------------------- |
| destructive | 25      | `oklch(0.54 0.18 25)`  | `oklch(0.96 0.015 25)`  | `oklch(0.65 0.14 25)`  | `oklch(0.22 0.03 25)`  |
| warning     | 70      | `oklch(0.55 0.16 70)`  | `oklch(0.97 0.015 70)`  | `oklch(0.72 0.14 70)`  | `oklch(0.22 0.03 70)`  |
| success     | 150     | `oklch(0.5 0.15 150)`  | `oklch(0.95 0.02 150)`  | `oklch(0.65 0.12 150)` | `oklch(0.22 0.03 150)` |
| info        | neutral | `oklch(0.55 0.02 260)` | `oklch(0.96 0.005 260)` | `oklch(0.65 0.02 260)` | `oklch(0.22 0.01 260)` |

クラス: accent → `text-{name}` / `bg-{name}`, tint → `bg-{name}-tint`
`-foreground` は accent 背景上のテキスト用（light: white, dark: dark text）。

### 2パターンに統一

セマンティックな色表現は以下の2パターンのみ。

| パターン                 | クラス構成                           | 用途                       |
| ------------------------ | ------------------------------------ | -------------------------- |
| **アウトライン（推奨）** | `border-{color} text-{color}`        | バッジ、タグ、警告ボックス |
| **塗り（アクション用）** | `bg-{color} text-{color}-foreground` | ボタン、アクション         |

対応カラー: `primary`, `success`, `warning`, `destructive`, `info`

### 置き換えルール

Container系・不透明度ハードコードからの移行ルール。

| 用途         | ❌ 旧（廃止）              | ✅ 新（推奨）                         |
| ------------ | -------------------------- | ------------------------------------- |
| バッジ       | `bg-*-container`           | `border-* text-*`                     |
| 警告ボックス | `bg-destructive-container` | `border-destructive text-destructive` |
| 選択状態     | `bg-primary-container`     | `bg-state-active`                     |
| アイコン背景 | `bg-primary-container`     | `bg-state-active` / `bg-muted`        |
| 不透明度背景 | `bg-warning/10`            | `border-warning text-warning`         |

## State（状態）

| トークン                       | Light                 | Dark                  | 用途                                              |
| ------------------------------ | --------------------- | --------------------- | ------------------------------------------------- |
| `bg-state-active`              | `oklch(0.95 0.019 H)` | `oklch(0.45 0.105 H)` | 装飾アイコン容器、`border-primary` を伴う状態補強 |
| `text-state-active-foreground` | `oklch(0.38 0.105 H)` | `oklch(0.88 0.045 H)` | `bg-state-active` の上の文字・アイコン            |

**この2つは必ずペアで使う。`bg-state-active` の上に `text-primary` を載せない。** dark では primary（`#4270bc`）と state-active（`#30548f`）の対比が 1.53:1 しかなく、アイコンがほぼ見えない。

`bg-state-active` は**選択行の地色ではない**。選択行と hover は foreground ベースの半透明 state layer（`bg-state-selected` / `bg-state-hover`）が担う。`state-active` は塗りの強い装飾容器と、`border-primary` で状態が伝わっている箇所の補強に使う。

そのため面との対比（dark で 2.3〜2.6:1）は WCAG 1.4.11 の 3:1 対象にならない。単独で状態を示す用途に使い始めるなら、その時点で明度を上げる必要がある（dark は L0.52 で card 比 3.14:1、ただし foreground 側を L0.94 まで上げないと 4.5:1 を割る窓の狭い領域）。

## Do's & Don'ts

### セマンティックトークンを使用

```tsx
// ✅ Do
<div className="bg-destructive text-destructive-foreground">エラー</div>
<div className="bg-success text-success-foreground">成功</div>

// ❌ Don't — 直接色指定
<div className="bg-red-500 text-white">エラー</div>
<div className="bg-green-500 text-white">成功</div>
```

理由: セマンティックトークンはダークモード対応を自動化し、デザイン変更時の一括修正を可能にする。

### アウトラインパターンの実例

```tsx
// WarningBox（破壊的操作の警告）
<div className="border-warning text-warning flex items-start gap-3 rounded-lg border p-4">
  <AlertTriangle className="size-5" />
  <div>この操作は取り消せません</div>
</div>

// InfoBox（補足情報）
<div className="bg-container rounded-lg p-4">
  <p className="text-sm font-medium mb-2">使用状況:</p>
  <ul className="text-muted-foreground space-y-1 text-sm">
    <li>Plans: 10件</li>
  </ul>
</div>
```

### 適切なテキストコントラスト

```tsx
// ✅ Do
<div className="bg-primary text-primary-foreground">正しい組み合わせ</div>

// ❌ Don't — 低コントラスト
<div className="bg-primary text-muted-foreground">読みにくい</div>
```

理由: WCAG 2.1 AA 基準（コントラスト比 4.5:1 以上）を満たすため。

### Surface 階層を守る

```
✅ container(沈む) → background(基準) → card(浮く)
❌ card → background → container（逆転）
```

理由: 視覚的階層。入力欄等の控えめな面には `bg-muted` を使用。

### 状態を色で表現

- ✅ 成功 → `text-success`、エラー → `text-destructive`、警告 → `text-warning`、情報 → `text-info`
- ❌ 成功を青で表示、エラーを黄色で表示、色だけで状態を伝える（アイコンなし）

## 色覚多様性への配慮（WCAG 1.4.1）

色だけで情報を伝えない。必ずアイコン・テキスト・形状を併用する。

```tsx
// ✅ Do — 色 + アイコン + テキストの三重伝達
<Badge variant="success"><CheckCircle2 /> 完了</Badge>
<Badge variant="destructive"><XCircle /> エラー</Badge>

// ❌ Don't — 色のみで状態を伝える
<span className="text-success">完了</span>  // 色盲ユーザーが識別困難
```

赤/緑の組み合わせのみで対比しない（protanopia/deuteranopia 対策）。
