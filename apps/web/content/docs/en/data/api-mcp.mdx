# Connect Claude or ChatGPT to Dayopt with MCP

Connect an AI assistant to your Dayopt account through MCP (Model Context Protocol). Each client uses OAuth. Review the access shown on Dayopt's consent screen before you approve it.

MCP connections require a Dayopt account. The permissions available depend on the client and on whether that client and account have been enabled for Dayopt's write beta.

## What an assistant can read

An authorized client can read the Dayopt data included in its granted permissions.

| Data        | What it includes                                      |
| ----------- | ----------------------------------------------------- |
| Plans       | Planned time, as a list or in detail                  |
| Records     | Time you actually spent, as a list or in detail       |
| Activities  | Activities and categories used to organize timeblocks |
| Segments    | Saved queries for analyzing your time                 |
| Review      | Statistics comparing plans and records                |
| Constraints | Busy time and rules used when placing plans           |

## Read and write permissions

ChatGPT Pro custom MCP apps can use read and fetch permissions in Developer Mode. They cannot use write actions through MCP. See [OpenAI's ChatGPT MCP guide](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt) for current availability and setup instructions.

Dayopt write access is a limited beta. It is available only when both the Dayopt account and the specific MCP client have been enabled, and the account meets Dayopt's current access requirements. A client that has not been enabled receives read-only access.

The consent screen lists the permissions for your connection. `write:plans` lets the client create and update Plans. `write:records` lets it create and update Records. `delete:plans` and `delete:records` let it move the matching data to trash and restore it. Review each permission before you approve it.

Write permissions let the client change the selected data directly when it runs a write action. The consent screen does not confirm each change for you. Check whether your client lets you review each write action before it runs. Keep the connection read-only if you cannot review those actions.

## Find your MCP server URL

1. Open Dayopt Settings and go to **Data Controls**.
2. Copy the URL in **MCP / API**.
3. Add that URL to your AI assistant and approve the requested access on Dayopt's consent screen.

## Connect Claude

1. In Claude, open **Customize → Connectors**.
2. Choose **+ → Add custom connector** and enter the name `Dayopt` and the URL copied from Dayopt.
3. In **Advanced settings**, set the OAuth Client ID to `claude-ai`. Leave the OAuth Client Secret empty.
4. Choose **Add**, connect to Dayopt, then review and approve the requested permissions.
5. In a chat, choose **+ → Connectors** and enable Dayopt for the conversation.

Claude can receive write permissions only when that Claude client and your Dayopt account are enabled for the write beta. Otherwise, its connection is read-only. See [Anthropic's remote MCP connector guide](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp) for current Claude instructions.

## Connect ChatGPT Pro

Use ChatGPT on the web. ChatGPT Pro custom MCP apps currently support read and fetch permissions only.

1. In ChatGPT on the web, enable **Developer Mode** in your settings. If you do not see this option, check OpenAI's current guide for your plan.
2. Open **Settings → Apps → Create** and create a custom app for Dayopt.
3. Enter the URL copied from Dayopt, scan the available tools, and complete the OAuth connection.
4. Sign in to Dayopt and approve the read access shown on the consent screen.
5. In a new chat, select the Dayopt app from the tools menu to use it.

If tool calls fail after Dayopt's tool list changes, review the custom app settings and scan the tools again, or recreate the app if needed. Follow [OpenAI's current setup guide](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt).

## Try a read and write flow

Select Dayopt in a chat. Use separate read tools to review Plans and Records:

> List my Plans and Records separately for [date], from [start of date] to [start of next date] in [time zone]. Keep planned and completed time separate.

If the consent screen grants `write:plans`, first ask for a draft without calling a Dayopt write tool:

> Draft one future Plan called [title] for [activity] from [start time] to [end time]. Use full ISO 8601 date-times with the correct UTC offset. Do not call a Dayopt write tool yet. Show me the title, activity, start time, and end time so I can review them.

After you review the draft, give a separate instruction to create it. The client applies the change when it calls `plans.create`. Check that the Plan appears in the Dayopt calendar.

If the consent screen grants `write:records`, use the same two-step process after an activity has happened:

> Draft one Record called [title] for [activity] from [past start time] to [past end time]. Use full ISO 8601 date-times with the correct UTC offset. Do not call a Dayopt write tool yet. Show me the title, activity, start time, and end time so I can review them.

After you review the draft, give a separate instruction to create it. The client applies the change when it calls `records.create`. A Record must end at or before the current time. Dayopt rejects a Record that ends in the future. For a negative check, request a Record that ends in the future and confirm that Dayopt rejects it and no Record appears. Create a Plan for future time instead. For example, `2026-10-05T09:00:00+09:00` is an ISO 8601 date-time with a UTC offset.

Use `plans.list` and `records.list` to read each type separately; both require `read:entries`. `activities.list` requires `read:activities` when you need to choose an activity. `review.get` compares Plans and Records for a date range of up to 31 days and requires `read:stats`. `entries.list` is also available when you want a combined list.

ChatGPT Pro supports read and fetch only, so it cannot run the write steps above. If the client does not show write access, keep using read-only tools and check the permissions on the consent screen.

## Revoke or reconnect

To revoke Dayopt access, open **Settings → Integrations → MCP connections** in Dayopt and revoke access for that client. You can also remove the connector in the client. Removing it from the client does not replace revoking access in Dayopt.

To reconnect, start the connection again from the client, sign in to Dayopt, and review the current permissions before you approve them.

## Troubleshooting

| Problem                                             | What to check                                                                                                          |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| No MCP server URL appears in Dayopt Settings        | Sign in to the Dayopt product and open **Settings → Data Controls**. If it is still missing, contact support.          |
| ChatGPT Pro cannot create or edit plans or records  | This is expected. ChatGPT Pro custom MCP apps currently have read and fetch permissions only.                          |
| The client cannot connect                           | Copy the URL from Dayopt Settings again and check for extra characters.                                                |
| The consent screen shows an error                   | Sign in to Dayopt in the same browser, then try again.                                                                 |
| ChatGPT reports a redirect URI error                | Stop the setup and contact Dayopt support with the error text.                                                         |
| Tools remain unavailable after a server change      | Reconnect and approve the current permissions. In ChatGPT, review the app settings and scan its tools again if needed. |
| You revoked access and want to use the client again | Reconnect from the client and approve a new connection.                                                                |

If the problem continues, [contact us](/contact).
