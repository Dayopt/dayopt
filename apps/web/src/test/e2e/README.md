# Public web browser flows

Run `PATH=/opt/homebrew/opt/node@24/bin:$PATH pnpm --filter @dayopt/web exec playwright test --workers=2 --reporter=line --output=/tmp/dayopt-web-playwright` from the repository root. For a remote run, set `WEB_E2E_BASE_URL` to the immutable URL of a verified READY nonproduction Web deployment with the intended source SHA. Deployment status, protection access and source identity must be verified separately: passing this suite does not establish them. For the working tree, omit WEB_E2E_BASE_URL: the existing Playwright webServer starts localhost:3001 with email, telemetry and Turnstile credentials disabled. Each test receives an isolated browser context. Desktop Chromium runs 95 cases. The Mobile Chrome project runs 18 @mobile cases: landing demos and explanations, header and signup navigation, footer language selection, consent controls, Docs article navigation, search-button submission and intercepted contact categories/validation. A local server is also accepted when Preview cannot represent the working tree. For local search, run `pnpm --filter @dayopt/web generate:search-index` before starting the server. Use `localhost` with Next dev; another host can be blocked by its development origin protection.

Coverage: English/Japanese landing plan and template demos; docs CTA to article; blog search clearing and article navigation; seven legal routes in both languages; locale menu; analytics consent permission, revocation and reload persistence; site search to docs; empty contact validation with intercepted mail delivery; theme selection and reload persistence; responsive header navigation; FAQ disclosure; four blog category tabs; docs keyboard search; blog pagination and filtering from page two; English/Japanese search submit, empty results, clearing and result filters with locale preservation; RSS responses in both languages; blog copy-link and clipboard failure feedback with canonical social-link targets; intercepted contact error, retry, success and new-message reset; every sitemap content route and internal content link rendered in its main region.

Additional interaction coverage: all landing content links; hero and closing animation replay; matching Product login destinations from desktop, mobile header and drawer; docs sidebar and previous/next links; table-of-contents heading/hash reload and issue reporting; search-dialog previews, recent searches, Escape and focus restoration; localized missing-doc recovery; blog/all filters and browser history; system-theme changes and localized controls; cookie-policy navigation, revocation cancellation preserving entered text and failed-storage feedback; contact field/error associations, length validation, every category, pending-send suppression, network/rate-limit errors and edited-request IDs. Blog clearing from page two restores that page. Delayed-JavaScript regressions verify that blog and site search accept edits only after their handlers are ready and then show the entered query's results. Delayed scripts resume through `route.fallback()` so the context network guard still runs. External Product login navigation is intercepted before network delivery; this verifies the Web destination, not authentication.

Further journeys preserve search queries, blog pagination and a shared Docs anchor when changing language; return the calendar demo to Record; open/collapse template and Google explanations; navigate article breadcrumbs, related articles and the all-articles link; open every Footer legal link and the third-party notice text in a guarded popup. Five signup controls per locale/device produce intercepted GET requests and the expected destination page. Native-share adapters verify the exact title/canonical URL on success, silent cancellation and clipboard recovery after permission failure, including the absence of unhandled promise rejections.

Every spec imports `public-test.ts`, which installs a context-wide network guard before navigation. It allows same-origin GET/HEAD and blocks other origins, mutating requests and Vercel telemetry paths; service workers are blocked. Individual contact and Product-navigation handlers fulfill synthetic responses before any delivery. Cookie permission tests verify browser-local consent without analytics transmission. No platform credentials or authenticated Product fixtures are needed. Turnstile on a remote deployment remains an explicit prerequisite when it disables submission; a failed prerequisite does not count as validation success.

HTTP checks outside browser routing use `public-get.ts`. API requests disable automatic redirects and verify the origin before every GET, including compatibility redirects. The Node fallback requires the same origin, an explicit GET, `redirect: 'error'` and a 15-second abort timeout. Its regression tests use two loopback HTTP servers to prove that another origin receives no direct or redirected requests; they make no provider calls. Playwright collects only `*.spec.ts`, while Vitest collects the adjacent helper unit tests.

Clipboard control tests exercise actual handlers with a browser clipboard adapter; they verify the exact written value and success/error feedback without accessing the host clipboard. Contact error/retry tests intercept every POST before interaction and verify request IDs, values and resulting UI. The content audit covers sitemap routes and links rendered in main, with transport failures retried through HTTP to handle development HTTPS upgrades. It verifies HTTP availability, not the visual correctness of every article.

No current docs contain a code block, so no public code-copy flow is reachable. `CopyCodeButton.test.tsx` verifies exact clipboard writes and rejected-write feedback at its component boundary. Native OS sharing is not exposed by headless Chromium; adapters exercise the share handler without invoking an OS share sheet or provider.

These tests do not prove real clipboard permissions, native OS sharing, actual mail delivery, analytics transmission, accessibility compliance, image/visual quality, browser variants, or authenticated product behavior. The unified suite retains metadata, screenshot, overflow and cross-tab consent checks. New flows must assert an outcome caused by the preceding action.
