# Public web browser flows

Run `WEB_E2E_BASE_URL=<Preview URL> pnpm --filter @dayopt/web exec playwright test` from the repository root. For the working tree, omit WEB_E2E_BASE_URL: the existing Playwright webServer starts localhost:3001. Each test receives an isolated browser context. Desktop Chromium runs the complete suite. The Mobile Chrome project runs only @mobile cases where the responsive controls differ: landing demos, drawer/header navigation, footer language selection and consent controls. A local server is also accepted when Preview cannot represent the working tree. For local search, run `pnpm --filter @dayopt/web generate:search-index` before starting the server. Use `localhost` with Next dev; another host can be blocked by its development origin protection.

Coverage: English/Japanese landing plan and template demos; docs CTA to article; blog search clearing and article navigation; seven legal routes in both languages; locale menu; analytics consent permission, revocation and reload persistence; site search to docs; empty contact validation with intercepted mail delivery; theme selection and reload persistence; responsive header navigation; FAQ disclosure; four blog category tabs; docs keyboard search; blog pagination and filtering from page two; English/Japanese search submit, empty results, clearing and result filters with locale preservation; RSS responses in both languages; blog copy-link and clipboard failure feedback with canonical social-link targets; intercepted contact error, retry, success and new-message reset; every sitemap content route and internal content link rendered in its main region.

Public production may be used only for these read-only navigation and browser-local state flows. Contact requests are intercepted before any action. Turnstile is an explicit prerequisite when it disables submission; a failed prerequisite does not count as validation success.

Clipboard control tests exercise actual handlers with a browser clipboard adapter; they verify the exact written value and success/error feedback without accessing the host clipboard. Contact error/retry tests intercept every POST before interaction and verify request IDs, values and resulting UI. The content audit covers sitemap routes and links rendered in main, with transport failures retried through HTTP to handle development HTTPS upgrades. It verifies HTTP availability, not the visual correctness of every article.

No current docs contain a code block, so no public code-copy flow is reachable. `CopyCodeButton.test.tsx` verifies exact clipboard writes and rejected-write feedback at its component boundary. Native OS sharing is not exposed by headless Chromium; the actual copy and social-link controls are covered.

These tests do not prove real clipboard permissions, native OS sharing, actual mail delivery, analytics transmission, accessibility compliance, image/visual quality, browser variants, or authenticated product behavior. The unified suite retains metadata, screenshot, overflow and cross-tab consent checks. New flows must assert an outcome caused by the preceding action.
