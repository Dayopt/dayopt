# Calendar

PlanとRecordを時間gridに描画するcomponent群。Storybookではviewごとの密度、2lane表現、drag state、empty stateを確認する。

## Visual contract

| View        | 確認する状態                                         |
| ----------- | ---------------------------------------------------- |
| Day         | 1日grid、Plan / Record lane、current time            |
| Week        | 7日密度、weekend、複数日の差分marker                 |
| Multi-Day   | 2〜7日の可変column                                   |
| Interaction | selection、drag preview、context menu、inline create |

- Planはoutline / 淡色、Recordは塗りを基本にする
- アクティビティ詳細は活動のメニューから明示的に開き、閉じた状態ではカレンダーの幅を使う
- Calendar Storyはpanel内部やDB data flowを説明しない

| ビュー        | 説明                   | コンポーネント |
| ------------- | ---------------------- | -------------- |
| **Day**       | 1日のタイムグリッド    | `DayView`      |
| **Week**      | 7日間のタイムグリッド  | `WeekView`     |
| **Multi-Day** | 2〜7日間のカスタム表示 | `MultiDayView` |

ビュー切替は `ViewSwitcherList` コンポーネントで行い、`CalendarNavigationContext` で状態管理。
アクティビティ詳細は直近30日の記録時間・1件あたりの中央値・記録一覧を表示する。実装は [ActivitySummaryPanel](../../activities/components/activity-summary/ActivitySummaryPanel.tsx) を参照する。Calendar の Story は時間軸表示と操作状態を扱う。

## コンポーネント構成

Calendar は controller、layout / Header、views / grid、activity filter、animation に責務を分ける。個々の実在ファイルは [components source](.)、ビューの描画分岐は [CalendarViewRenderer](controller/components/CalendarViewRenderer.tsx) から確認する。ここには file tree の写しを置かない。

## 状態管理

### 状態の責務

| 状態                           | 所有する責務                        | 正本                                                                           |
| ------------------------------ | ----------------------------------- | ------------------------------------------------------------------------------ |
| フィルター                     | アクティビティごとの表示設定        | [FilterStore](../stores/useCalendarFilterStore.ts)                             |
| drag / scroll / 表示状態       | Calendar 内の一時 UI 状態と表示設定 | [stores source](../stores)                                                     |
| 日付 / ビュー / ナビゲーション | URL と Calendar の表示範囲          | [CalendarNavigationContext](../hooks/navigation/CalendarNavigationContext.tsx) |

実在する store / Context の一覧と型は source から確認する。アクティビティ詳細の開閉状態は共通 store が持ち、カレンダーの表示日・viewから独立している。

## ドラッグ & ドロップ

- **技術**: native pointer events（`onPointerDown` 起点の自前実装）。外部 DnD ライブラリは
  サイドバーの並べ替え廃止に伴い依存ごと撤去済み（#2162）
- **対象**: カレンダーグリッド上のタイムブロックの移動・リサイズ
- **状態**: `useCalendarDragStore`（ドラッグ元・ゴースト・プレビュー時間）
- **機能**: ドラッグプレビュー、時間計算、モバイルハプティクス

サイドバーのアクティビティは並べ替えできない（名前順に固定）。カテゴリーの
付け替えは行メニューの「カテゴリーを変更」で行う。

---

## フィルター

アクティビティごとの表示を切り替える。アクティビティ未設定のブロックは常に表示し、「アクティビティなし」の表示トグルは持たない。カテゴリー未所属のアクティビティとは区別する。

状態・保存方式・表示判定の正本は [FilterStore](../stores/useCalendarFilterStore.ts)。

## データ同期

`refetchOnWindowFocus`（TanStack Query）でタブ切り替え時にデータを自動再取得。

---

## DB テーブル

| テーブル     | 用途                                                                    |
| ------------ | ----------------------------------------------------------------------- |
| `plans`      | 計画（タイトル、時間、`activity_id` 等）                                |
| `records`    | 実際に使った時間（予定とは独立）                                        |
| `activities` | Plan / Record の分類単位（`plans.activity_id` / `records.activity_id`） |
| `categories` | アクティビティの所属先。色・アイコンを持つのはこちら                    |

---

## キーボード操作

- ビュー切替、日付ナビゲーション、プラン選択
- 選択中の Plan / Record をコピーし、同じ種別の独立した Timeblock として貼り付け
- 週末トグルショートカット
- Escape でキャンセル
