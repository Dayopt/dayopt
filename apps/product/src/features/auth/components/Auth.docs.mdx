# Auth

Supabase Auth ベースの認証システム。OAuth、MFA、セッション監視をサポート。

---

## 認証フロー

```
ユーザーアクセス
├── 未認証 → AuthLayout（ログイン/サインアップフォーム）
│   ├── メール/パスワード認証
│   └── OAuth（Google のみ。Apple / Meta は不採用）
│       └── 認証成功 → セッション確立
├── MFAチェック
│   └── MFA有効 → MFA認証画面
└── 認証済み → proxy が protected path を通す → アプリ表示
    └── SessionMonitor → 非アクティブ監視
        └── タイムアウト → SessionTimeoutDialog

認証メール（signup 確認 / recovery / email_change）
└── メール内リンク → /auth/confirm で verifyOtp → next へ着地
```

---

## コンポーネント構成

```
AuthLayout                      認証ページレイアウト
├── LoginForm                   メール/パスワード + Google ボタン
├── SignupForm                  登録フォーム（メール確認付き）
├── PasswordResetForm           リセットメール送信
├── ResetPasswordForm           新パスワード設定（confirm 経由で着地）
└── MFAVerifyForm               TOTP / リカバリーコード検証

AuthStoreInitializer            Server Component からストア初期化

SessionMonitorProvider          セッション監視プロバイダー
└── SessionTimeoutDialog        非アクティブ警告ダイアログ
```

ルート保護のコンポーネントは持たない。認証ガードは proxy（`src/proxy.ts`）に一元化している。

## 状態管理

### useAuthStore

| State     | 説明                       |
| --------- | -------------------------- |
| `user`    | Supabase User オブジェクト |
| `session` | セッション情報             |
| `loading` | 認証処理中                 |
| `error`   | エラー状態                 |

| Action                      | 説明               |
| --------------------------- | ------------------ |
| `signIn(email, password)`   | メール認証         |
| `signUp(email, password)`   | 新規登録           |
| `signInWithOAuth(provider)` | OAuth認証          |
| `signOut()`                 | ログアウト         |
| `resetPassword(email)`      | パスワードリセット |
| `updatePassword(password)`  | パスワード更新     |

state / action、middleware、セッション初期化のタイムアウトとオンライン / オフラインの条件は [useAuthStore.ts](../stores/useAuthStore.ts) を正本とする。ここでは一律の秒数を複製しない。

## セキュリティ

| 対策               | 説明                                                                             |
| ------------------ | -------------------------------------------------------------------------------- |
| OWASP準拠          | パスワードリセットはメール存在を漏らさない（常に成功扱いで返す）                 |
| エラーサニタイズ   | `lib/auth-error.ts` の `getAuthErrorKey`（`sanitize-auth-error` から re-export） |
| Bot 対策           | Cloudflare Turnstile（`lib/turnstile`）+ Supabase Auth Bot Protection            |
| 漏洩パスワード検査 | `lib/auth/pwned-password.ts`（Have I Been Pwned）                                |
| MFA 強制           | proxy と tRPC `protectedProcedure` の二層で AAL を fail-closed 判定              |
| リカバリーコード   | `lib/auth/recovery-codes.ts`。HMAC pepper 付きで hash 保存                       |

## OAuth プロバイダー

Google のみ。本番の provider 設定は Supabase Dashboard が正本
（Apple は有料 Developer Program が必須のため不採用、Meta は審査コストのため不採用。2026-07 決定）。

## バリデーション

| スキーマ         | バリデーション                             |
| ---------------- | ------------------------------------------ |
| `loginSchema`    | メール形式、パスワード必須                 |
| `signupSchema`   | メール形式、`passwordSchema`               |
| `passwordSchema` | 8〜64 文字。signup / リセット / 変更で共通 |

Zod ベース。エラーメッセージは i18n キー（`auth.errors.*`）を持ち、表示側で `t()` 解決する。
英数字必須（`letters_digits`）の検証は Supabase 側が行う。
